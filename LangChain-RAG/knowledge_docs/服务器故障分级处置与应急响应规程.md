# 服务器故障分级处置与应急响应规程
## 1. 目的与适用范围
为标准化处理企业机房x86机架服务器、刀片服务器、存储节点硬件及系统故障，统一故障分级标准、响应时限、处置流程、复盘规范，最大限度缩短业务中断时间、降低数据丢失风险、规范运维操作行为，保障核心业务系统高可用稳定运行，特制定本处置规程。本规程适用于机房所有生产服务器、测试服务器、灾备服务器、虚拟化宿主机硬件故障、系统异常、阵列降级、电源故障、内存报错、风扇异常、主板告警等各类硬件异常场景。
## 2. 故障分级定义（P1/P2/P3 三级标准）
### 2.1 P1 一级严重故障（重大故障）
定义：服务器整机宕机、操作系统崩溃、业务完全中断、集群节点离线、核心数据库节点异常、RAID阵列多盘故障、整机断电重启、虚拟化集群资源离线，直接影响用户正常使用、造成业务停滞。
响应要求：7×24小时立即响应，10分钟内确认故障影响范围，30分钟内启动应急处置，优先恢复业务，后定位硬件问题。全程实时同步故障进展至部门负责人及业务对接人。
### 2.2 P2 二级一般故障（轻度影响）
定义：服务器硬件单体故障但业务未中断，包含单电源失效、单块硬盘故障导致RAID阵列降级、单条内存报错、单风扇异常，设备仍可正常运行，但存在潜在宕机风险。
响应要求：工作时间2小时内到场排查，4小时内制定更换方案，24小时内完成硬件替换与隐患消除，夜间非工作时段次日优先处理。
### 2.3 P3 三级告警故障（无业务影响）
定义：设备传感器告警、温度轻微异常、风扇转速波动、日志报错、临时偶发报错，无业务中断、无阵列降级、无性能影响，属于潜在隐患类问题。
响应要求：统一汇总至运维隐患台账，日常运维窗口集中排查处理，一周内完成隐患闭环。
## 3. 常见服务器故障现象与风险说明
### 3.1 硬盘与RAID阵列故障
服务器硬盘故障表现为机房设备黄灯告警、BMC管理界面硬盘状态Critical、阵列日志提示磁盘离线、阵列降级。RAID5架构单盘故障可正常运行，双盘及以上故障直接导致阵列崩溃、数据丢失、业务瘫痪。RAID10架构容错性更高，但连续多盘故障同样存在数据损毁风险。阵列降级期间严禁拔插正常硬盘、严禁重启服务器、严禁变更阵列配置，避免二次事故。
### 3.2 电源模块故障
核心服务器均配置双电源冗余架构，单电源离线、电源告警、电源负载异常时，设备可依靠单路电源持续运行，但失去冗余保护，若市电波动、另一路电源故障会直接导致整机断电宕机。发现电源故障需尽快采购、更换备件，消除单点故障风险。
### 3.3 内存故障
内存分为CE可纠正错误与UCE不可纠正错误。CE报错为轻微偶发报错，可持续观察；UCE致命报错会直接触发服务器蓝屏、重启、系统崩溃、业务中断。频繁内存报错需及时更换故障内存，避免系统不稳定。
### 3.4 风扇与温度故障
风扇损坏、转速过低会导致服务器温度升高，高温会触发设备降频、自动保护重启、硬件老化加速，长期高温运行会大幅缩短服务器使用寿命，增加整机故障概率。
## 4. 标准化故障处置流程
第一步：告警确认与影响评估。接收动环告警、监控告警、业务反馈后，第一时间登录BMC、iDRAC、IPMI管理界面查看硬件状态、SEL日志、传感器数据，确认故障部件、故障时间、影响节点、业务范围。
第二步：业务优先保障。P1故障优先进行业务切换、集群迁移、备用节点上线，优先恢复用户业务，再开展硬件故障定位排查。
第三步：故障取证留存。导出硬件日志、系统日志、告警截图、阵列日志，完整留存故障证据，用于后续复盘分析与故障定级。
第四步：故障排查与备件更换。确认故障部件后，申请备件、预约维护窗口，严格按照机房设备操作规范完成硬件更换、上架、接线、测试。
第五步：恢复验证与持续观测。更换完成后检查设备告警清除状态、阵列重建进度、设备温度、负载状态、业务运行状态，持续观测2-4小时，确认无复发告警、业务运行稳定。
第六步：台账更新与复盘归档。更新设备资产台账、故障处置台账，填写故障原因、处置过程、整改措施、预防方案，完成闭环归档。
## 5. 高危禁止操作规范
1. 阵列降级状态下禁止拔插正常硬盘、禁止重启服务器、禁止修改阵列参数。
2. 业务高峰期禁止无预案停机、禁止随意断电、禁止批量调整硬件配置。
3. 未备份日志、未留存证据前禁止直接清除硬件告警。
4. 无运维主管审批，禁止外来厂商直接操作生产核心服务器。
## 6. 故障复盘与优化机制
所有P1、P2故障必须完成书面复盘报告，分析故障根因、操作漏洞、监控盲区、运维短板，制定整改措施、预防机制、优化方案，纳入日常运维改进计划，降低同类故障重复发生概率。
